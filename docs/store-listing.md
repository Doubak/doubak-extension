# Chrome 应用商店提交表单：可直接粘贴的答案

后台每个权限都要你写一段「为什么需要」，写得含糊会被打回来重填。下面这些是照
[`permissions.md`](permissions.md) 改的，每条都说清**要它干什么**、**不要它会怎样**，
以及**为什么不用更宽的那条**——审核最想看到的就是最后这一点。

改动权限时，这份和 `permissions.md` 要一起改。

---

## 基本信息

| 字段 | 填什么 |
|---|---|
| 名称 | 豆备 Doubak |
| 简短说明（132 字以内） | 在你自己的浏览器里备份豆瓣数据，存成标准 WARC 档案。所有数据留在本地。 |
| 类别 | 生产力工具（Productivity） |
| 语言 | 中文（简体） |
| 隐私政策 URL | `https://doubak.com/privacy/` |
| 官网 | `https://doubak.com` |
| 支持 / 反馈 | `https://github.com/Doubak/doubak-extension/issues` |

### 详细说明（草稿）

> 豆备把你的豆瓣内容备份到你自己手里：标记（想看／在看／看过）、短评、评分、
> 标签、广播、日记与影评，连同你自己上传的图片。
>
> **它在你自己的浏览器里跑，用你已有的登录状态。** 没有服务器，没有账号，
> 不上传任何东西——你的密码和 Cookie 一步都不经过第三方。
>
> 存下来的是标准 **WARC** 档案加一份 JSON 索引：用 `jq`、pywb、
> ReplayWeb.page 都能直接打开，不依赖本工具。十年后仍然读得懂。
>
> 还可以把档案解析成结构化数据，生成一个属于你自己的静态豆瓣站点
> （示例：sample.doubak.com）。
>
> 开源，Apache-2.0。源码与逐条权限审计：github.com/Doubak
>
> ⚠️ 豆备是独立的第三方开源工具，与豆瓣网及其运营方没有任何关系，
> 也未获其授权或认可。

**那句免责声明别删。** 它既是事实，也是把「第三方工具」与「官方产品」分开的那道线。

## 权限理由

### `unlimitedStorage`

> 备份下来的档案动辄几百 MB（实测一次全量抓取约 170 MB，含图片）。不声明这条，
> 浏览器的默认配额放不下，抓到一半就会失败。它同时也是档案**不被浏览器在磁盘
> 压力下清掉**的实际保护——扩展里 `navigator.storage.persist()` 恒返回 false，
> 防驱逐靠的就是这条权限。

### `alarms`

> 抓取是几小时起步的长任务，而 MV3 的 service worker 空闲约 30 秒就会被杀。
> 闹钟是**唯一一个在 worker 被杀之后仍然存在**的东西，用来把它叫醒继续。
> 没有它，抓取会在用户切走标签页之后静默停止。

### `offscreen`

> 抓取本体跑在 offscreen document 里，因为 service worker 不是专用 Worker，
> 用不了 `createSyncAccessHandle()`，也就写不了 OPFS。档案必须流式写入
> （不能在内存里拼一个几百 MB 的 Blob），所以这条是必需的。

### `notifications`

> 豆瓣要求验证码、或登录状态失效时，抓取会**停下来等人**——它不会自动重试，
> 那样可能导致用户账号被限制。这时需要把用户叫回来。没有通知的话，用户会
> 以为还在跑，几小时后回来发现什么都没发生。

### `declarativeNetRequestWithHostAccess`

> **只为一件事：给豆瓣图片请求补上 `Referer` 头。**
>
> 豆瓣图片域（`doubanio.com`）有防盗链，不带 Referer 一律返回 `418`
> （13 字节，还标着 `image/jpeg`）——直接在地址栏打开图片 URL 也是同样的结果。
> 而 `Referer` 是 `fetch()` 的禁改头，代码里设了会被丢掉，唯一的途径就是
> DNR 的 `modifyHeaders`。
>
> 规则只作用于 `tabIds: [-1]`（不属于任何标签页的请求，即扩展自己发出的），
> **不碰用户正常浏览的流量**。
>
> **为什么不用 `declarativeNetRequest`**：那一条允许改任意站点的请求，安装警告是
> 「屏蔽任意网页上的内容」。带 `WithHostAccess` 的这条把作用范围限死在已有
> `host_permissions` 的站点上——能力更小，而我们要的恰好就只有豆瓣。

### `host_permissions`：`https://*.douban.com/*`、`https://*.doubanio.com/*`

> 这是这个扩展的全部工作对象：`douban.com` 是内容，`doubanio.com` 是图片域。
> 两者都限定 `https`。**没有声明任何其他站点**，也没有 `<all_urls>`——
> 浏览器因此不会允许它连接别处，这也是隐私政策那句「数据不离开本地」的技术兑现。

### 明确没有要的

> `tabs`：唯一的用处是 `chrome.tabs.create({ url })` 打开面板，而那**不需要**
> 这条权限（它只管 `url` / `title` / `favIconUrl` 这些敏感字段）。它换来的警告是
> 「读取你的浏览历史」——对一个主打「数据不离开本地」的工具来说，那是不该付的代价。
>
> `cookies`、`webRequest`、`storage`（用的是 OPFS 与 IndexedDB）、`scripting`、
> `<all_urls>`：都不需要，也都没有声明。

## 数据用途申报（Data safety）

后台会让你逐项勾选并声明。照实填：

| 问题 | 答案 |
|---|---|
| 收集个人身份信息？ | **否** |
| 收集健康 / 财务 / 位置 / 通信内容？ | **否** |
| 收集用户活动、网页浏览记录？ | **否** |
| 收集网站内容？ | **否**——数据只写入用户本机存储与用户自选的文件夹，不传输到任何服务器 |
| 出售给第三方？ | **否** |
| 用于与核心功能无关的用途？ | **否** |
| 用于判定信用 / 贷款？ | **否** |

三项声明都要勾：**不出售**、**不用于核心功能之外的用途**、**不用于信用评估**。

> 关键区别：「读取」不等于「收集」。扩展确实读取用户的豆瓣页面，但它**没有
> 任何接收端**——项目没有服务器。数据从浏览器写到用户自己的磁盘，仅此而已。

## 提交前自查

- [ ] `node tools/package.mjs` 通过，`dist/` 里的 zip 解开后 `manifest.json` 在根部
- [ ] `npm test` 全绿
- [ ] `manifest.json` 与 `package.json` 版本一致，且**高于**上一个已发布版本
- [ ] 隐私政策页 <https://doubak.com/privacy/> 可访问
- [ ] 至少一张截图（1280×800 或 640×400）
- [ ] 详细说明里带着那句第三方免责声明
- [ ] **用一个没登录豆瓣的浏览器配置打开面板**，确认显示的是一句清楚的提示，
      不是报错或空白——审核员多半没有豆瓣账号，那就是他看到的第一屏

## 发布之后

首次审核通常几天；之后每次更新都要重新过审。

**建议先发 unlisted 或受信任测试者。** 这个扩展碰的是用户的登录会话，而目前
只有一个账号完整跑过（见 README「现状」）。等有几个人跑通再转公开。
