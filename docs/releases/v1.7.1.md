## v1.7.1：导出空间不足与 ZIP 中转清理修复

本次是 v1.7.0 的修复版本，主要处理 [#35](https://github.com/Doubak/doubak-extension/issues/35)。

### ZIP 导出失败与清理

- ZIP 任一成员写入失败即停止整包，不再继续导出后面的档案；不交付半成品下载，不登记“已导出”。
- 初始化、写入、收尾或读取成品失败均尝试清理；使用 abort 放弃失败写入，避免 close 提交半份 ZIP。清理失败会保留原始错误并明确提示。
- 已交给下载的 ZIP 不因后续界面或导出记录错误而被删除。Chrome／Edge 的原子目录写入失败也会放弃新副本，保留原有目标文件。
- 修复同时覆盖**「档案」的原始导出与「导出」的结构化数据、NeoDB、Markdown**。

### 空间提示与中转管理

- 「档案」页新增 ZIP 中转占用、浏览器剩余配额估算，以及「清理 ZIP 中转文件」按钮；只清专用中转目录，不删除原始档案。
- 清理和打包共用跨面板锁。手动清理或下一次导出前，需确认旧下载已完成或取消；统计文件大小失败也保留清理入口。
- 等待浏览器真正释放打包锁后才结束操作，修复 Firefox 完成、取消或失败后立即重试／清理误报“另一个面板正在打包”的时序问题。
- 原始档案 ZIP 按实际成员大小预检配额，明显不足时在写入前停止。派生输出压缩大小未知，不以源档案大小作硬性拦截。
- 区分浏览器配额与物理磁盘空间，提示检查浏览器配置文件和下载目录所在磁盘；整条链过大时可逐份导出，保留全部祖先档案。
- Firefox 仍需要中转 ZIP 和下载文件各一份空间；浏览器可能延迟回收。ZIP 失败后需要重新打包，不能续导。

### 存储读取

- 修复目录删除／重建后，Worker 继续使用旧句柄而持续报 `Entry not found` 的情况。
- 只读扫描不再创建缺失目录；扫描中遇到 NotFoundError 重列一次，持续错误仍明确报告，不无限重试、不隐藏档案。
- 原报告没有错误堆栈，该修复不表示所有同名错误都已归因于失效句柄。

### 兼容性与验证边界

- 档案格式继续为 **bundle/1.5**；旧档案、ZIP 内部布局、账号隔离及导出命名规则不变，不迁移或改写原始档案。
- 浏览器权限及最低版本不变，Firefox 仍要求 **142+**；没有增加下载记录权限。
- 自动化覆盖配额不足、初始化／写入／收尾／取成品／清理失败、再次导出、导出记录、跨面板互斥、目录重建，以及旧目标文件保留；完整回归与两个时区的 CI 均作为发布检查。
- Firefox 155 独立测试配置下，使用真实 OPFS 与写入流验证 ZIP 成功、取消、注入配额错误后的清理及立即重试；独立 ZIP 读回校验 CRC 和文件字节，源文件未变。用户原先磁盘用尽环境的实际复测仍待进行。配额估算不能保证物理磁盘空间，浏览器下载阶段是否成功仍需在下载列表确认。
- GitHub Release 与 Chrome Web Store／AMO 分别发布，商店安装包需要另行提交审核。

另补充了 Firefox 155 广播详情／回复首屏的真实导出验收，并整理已实现设计文档；不新增广播采集范围。
详细依据：[导出空间与清理审计](https://github.com/Doubak/doubak-extension/blob/v1.7.1/docs/designs/done/export-storage-pressure.md)。
