# 权限审计

这个扩展要碰的是用户的登录会话和几年的个人数据，权限清单就是**用户看到的那份
承诺**——安装时的警告文字直接从它生成。所以这份清单多一条少一条都不是小事：
多一条是要了用不上的权力，少一条是运行时突然失败。

一致性由 `test/manifest.test.js` 双向钉住：声明了的必须用得上，用到的必须声明。

## 现在声明了什么

| 权限 | 为什么要 | 安装警告 |
|---|---|---|
| `storage` | `chrome.storage.local` 存 checkpoint 与当前抓取指针 | 无 |
| `unlimitedStorage` | 不声明的话几百 MB 的档案放不下。**它也是 OPFS 不被浏览器在磁盘压力下清掉的实际保护**（`persist()` 在扩展里恒为 false，见 DESIGN.md 附录 C.9） | 无 |
| `alarms` | 心跳。service worker 约 30 秒空闲即被杀，闹钟是**唯一一个我们死了它还在**的东西 | 无 |
| `https://*.douban.com/*`<br>`https://*.doubanio.com/*` | 抓取本体；`doubanio` 是图片域 | 「读取和更改你在 douban.com 上的数据」 |

就这些。

## 明确不要的

### `tabs` —— 已删

唯一的用处是 `chrome.tabs.create({ url })` 打开面板和自检页，而**那不需要
`tabs` 权限**：这条权限只管 `url` / `pendingUrl` / `title` / `favIconUrl` 这些
敏感字段。

它换来的安装警告是「**读取你的浏览历史**」。对一个主打「数据不离开本地」的
扩展，这一句会直接让人卸载——而且我们本来就没用到。

### `web_accessible_resources` —— 已删

原先把 `selftest/*` 与 `src/ui/*` 暴露给 `<all_urls>`。这是纯粹的多余：WAR 只在
**网页或内容脚本**要加载扩展资源时才需要，而我们没有内容脚本，面板和自检页都是
通过 `chrome-extension://` 直接打开的。

代价却是实的：**任何网站都能探测那个资源加不加载得出来，从而判断用户装没装
豆备。** 对这个项目的用户群来说，「装了一个豆瓣备份工具」本身就是一条不该外泄
的信号。

### `notifications` —— 不要，用角标代替

`awaiting_human`（验证码、软封锁）确实需要把用户叫回来。但通知权限会多一句安装
警告，而角标 + 标题（`chrome.action.setBadgeText` / `setTitle`）零权限就能做到，
且与「这是暂停不是错误」的设计一致——一个跳出来的系统通知更像出事了。

代价要说清：**角标可能几小时都没人看见**，那段时间抓取是停着的。如果实测发现
这真的成问题，再加通知权限，届时它是一次有理由的权限扩张，而不是顺手要的。

### `optional_permissions` —— 想过，不做

运行时才申请 douban.com 的访问权，安装警告会好看一点。但这个扩展**没有那个权限
就什么都做不了**，把必需的东西做成可选的，只是把「装不上」推迟成「用不了」，
还多一条失败路径。

安装时就明说要读写 douban.com，反而与项目立场一致：请求全部来自你自己的浏览器
和 IP，凭据一步都不离开设备。

## 还要加的

| 权限 | 什么时候 | 为什么 |
|---|---|---|
| `offscreen` | 随 F-10d | service worker **不是**专用 Worker，`createSyncAccessHandle()` 在里面不可用。OPFS 写入必须搬进 offscreen document 里的专用 Worker。无安装警告 |
| `declarativeNetRequest` | 只在启用 Rexxar 接口路线时 | 改写 `Referer`。广播路线是纯 HTML，不需要它——所以 M0 不加 |

`webRequest` 目前只出现在注释里（用来补齐真实响应头的方案），没有任何调用，
因此不声明。

## 权限在抓取途中丢掉怎么办

这是最容易被漏掉的一类，因为它在开发和测试里几乎不会发生。

Chrome 允许用户在**任何时刻**把站点访问改成「点击时」或「仅特定网站」——
chrome://extensions 里两下就改完了，不需要重装、也不会通知我们。一场几小时的
抓取跨过这种改动是完全现实的。

**问题在于权限被撤之后 `fetch()` 抛的是 `TypeError`，和网络故障一模一样。**
默认分类会把它判成可重试的网络错误，然后一遍遍重试一个永远不会自己好的问题。
用户看到的是「网络怎么这么差」，真实原因是权限没了,他毫无线索。

这和「把风控当网络错误去重试」是同一类错误，只是代价不同：那边赔的是账号，
这边赔的是几小时加一个查不出原因的失败。

所以有两道处理：

1. **主动**：`chrome.permissions.onRemoved` 一响就暂停，停机原因
   `host_permission_lost`，并把角标点亮。
2. **兜底**：`fetch()` 失败**之后**查一次权限（`src/crawl/permissions.js`）。
   查出来没权限就换成不可重试的 `PermissionError`，整场停下。

兜底那道也必须有——`onRemoved` 事件在 service worker 已死时可能唤醒不及，而
下一次 fetch 一定会撞上。反过来只靠兜底也不行：那意味着已经白发了一次请求、
白等了一轮重试。

三条配套规则：

- `checkHostAccess()` 在 API 不可用时返回 `null` 而**不是** `true`。「查不了」
  和「有权限」是两件事——把前者当后者，等于在 Node 测试里悄悄关掉了整条检查。
  （这正是这个 bug 第一次被漏掉的方式。）
- 权限检查只在**失败之后**做，不在每次请求前做。每页查一遍权限，是给一件极少
  发生的事付常态开销。
- 恢复策略里 `host_permission_lost` **不自动恢复**，理由和风控还不同：这里根本
  不是等一等就好，权限得用户去改，而 `permissions.request()` 必须在用户手势里
  调用,后台自己发起不了。

## 存储写失败怎么办

原先 `quota` 这个停机原因在恢复策略和界面文案里都有，但**从来没有任何代码抛出
它**——磁盘满了会以一个未捕获的异常结束这一批，界面上什么都不显示，闹钟接着
一次次撞同一面墙。

现在写失败在 `CrawlLoop` 里被捕获并分成两类（`src/storage/quota.js`）：

| 原因 | 下一步 |
|---|---|
| `quota` | 用户去导出或清理。重试没有意义 |
| `write_failed` | 先跑一次崩溃恢复把段尾可能撕裂的半条记录切掉，再继续 |

两者都让**整场**抓取停下，而不是只把该路线标失败然后继续。写入器的契约是
「每页都落盘」，这条契约一破，索引里的偏移量、连续性证明、`captured` 计数全都
建立在假前提上；而后续的写大概率同样失败，每一次都可能在段尾留下撕裂的记录。
停下来只需一次崩溃恢复就能修好,接着写下去是一路撕裂到用户放弃。

配额耗尽的名字在各浏览器/API 上不统一（`QuotaExceededError`、legacy
`code === 22`、只在 message 里带字样），都认下来——认漏了就会把「磁盘满了」
显示成「未知错误」,而这两句话对用户的意义完全不同。

## 文件系统访问权限（导出）

`showDirectoryPicker()` 拿到的目录句柄：

- **必须在用户手势里调用。** 现在是按钮直接触发，满足。将来若在异步等待之后
  再要句柄，手势就过期了——那是个容易踩的坑。
- **句柄不跨会话保存。** 所以每次导出都要重新选目录，也就没有「中断续导」
  （F-08i，未实现）。要做的话得把句柄存进 IndexedDB 并在下次
  `requestPermission()`,那是一次真实的权限再确认,不能想当然。
- 目的地**非空默认拒绝**。文件选择器里随手点中的可能是文档目录，同名即覆盖，
  而覆盖掉的东西没有回收站。

## 不能撤销、但仍会失败的

`unlimitedStorage` 是必需权限，用户没法单独收回它。但**配额解除不等于磁盘无限**:
盘满了照样写不进去,走上面那条 `quota` 路径。

`persist()` 在扩展里恒为 `false`,这是预期行为而非风险信号(保护来自
`unlimitedStorage`)。界面上刻意不显示它——摆出来只会制造假的不确定性。
详见 DESIGN.md 附录 C.9。
