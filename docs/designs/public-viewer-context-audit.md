| 影视/书/音乐/舞台剧标记列表 | 目标账号条目的评分、短评、日期、标签 | 标记从列表条目产生；匿名缺失 tags 保留 omitted。作品详情的个人控件不能补这些字段。 |

“公开抓取”不等于“整张 HTML 只包含目标内容”。账号列表、长文等仍按已绑定的操作者访问，
原始 WARC 可能包含导航、回复、社区内容；它是页面证据，不能直接作为已过滤的公开站点发布。
此次不修改历史 WARC。公开作品目录改为无凭据请求，是减少原始页面中无关个人评价的一道防线，
并不保证豆瓣返回页没有社区评论或其他上下文。派生输出继续依赖各内容容器/作者过滤。

## 恢复与回归

请求策略在每次 `_fetchOne` 根据已锁定运行视角和路线重新决定，不依赖新增 checkpoint 字段。
因此旧断点中已排队的目录 URL 冷恢复后同样无凭据；manifest 的操作者仍记录原操作者。
目录返回退出登录导航不再误报操作者退出；豁免只作用于该响应，下一张账号页面仍检查换号/退出，
恢复前的目标和操作者握手保持原规则。异常目录响应若仍显示登录者，记为 `unknown` 并停止，
保留证据但禁止解析摄取。不因验证码或限流失败自动换身份重试。

测试覆盖首次/冷恢复的五类作品 URL、本人目录、异常登录响应、后续账号页换号/退出、
重定向无凭据、ck 拒绝、最小间隔与退避，以及详情控件对 canonical 的隔离。

## Chrome 开始消息回归

在独立 Chromium 扩展环境使用模拟豆瓣响应复现：查看 `154611037` 成功，开始时出现
`The message port closed before a response was received.`。原因是 `start.target` 的账号对象
被后台 `if (msg.target) return` 当作离屏地址丢弃；现仅排除 `OFFSCREEN_TARGET` 字符串。
另修正冷启动竞态：离屏文档存在不代表模块监听器就绪；先以有界 ping 握手等待，再发一次写命令。
不会自动重发 start。Node 测试执行真正后台监听器，浏览器验证实际跨上下文消息链路。

最终验证：扩展 `npm test` 2,061 通过、0 失败、1 个既有跳过；解析器 307 通过、
0 失败、1 个既有跳过。vendor 逐字节校验包含在测试中。Chromium 156 独立测试档案中，
模拟豆瓣响应，经真实 service worker/offscreen/OPFS 消息链路，公开目标开始成功，
随后本人开始成功；没有使用真实豆瓣 Cookie 或发起实网抓取。
