# 导出空间不足与 ZIP 中转清理（#35）

2026-11-12，main 上的待发布修复；不代表已发布的 v1.7.0 含这些修改。
后续版本：修复纳入 [v1.7.1](../../releases/v1.7.1.md)；下文保留修复时的调查与验证记录。
问题：[Firefox 打包 Quota exceeded，偶发 Entry not found](https://github.com/Doubak/doubak-extension/issues/35)。

## 查明的问题

- Firefox 把 ZIP 流式写入 OPFS，再以 File/object URL 交给下载。原始档案之外仍需要中转 ZIP 和下载文件各一份空间。
  WARC 段已经 gzip 压缩，重复压缩不能消除这两份副本；改成整包 Blob 会增加整包级别的内存占用。
- 整条链逐份捕获异常后继续，并最终尝试完成同一个 ZIP，可能掩盖最初的空间错误。
- 失败／取消调用 close 提交半份 ZIP，清理目录的所有错误又被忽略；初始化失败也可能留下中转文件。
- 没有可见的中转占用或手动清理入口；下次导出直接删除上一次文件，无法知道那个下载是否仍在进行。
- OPFS Worker 缓存目录句柄。目录被其他 Worker 删除并重建后，旧句柄仍失效，即使重扫也继续报 NotFoundError。
  已通过具有删除／重建语义的测试复现；issue 没有堆栈，不能断言用户每次 Entry not found 都源自这一原因。

## 修复

1. 任一 ZIP 成员写入失败即停止整包，保留原始错误，不触发下载，也不记已导出。初始化、写入、收尾、取成品失败均清理；
   用 abort 放弃原子写入，失败后的 abort 可重复调用。已交付下载的 ZIP 不因后续界面／导出记录错误而被删除。
   目录写入失败也优先 abort，保留旧目标文件；目录整链仍逐份报告，单份失败不阻止其他档案导出。
2. 原始档案 ZIP 读取文件大小，加成员头部余量，清理旧中转后再检查浏览器配额。明显不足时在写入前拦截。
   估算 API 不可用时不宣称空间充足，也不阻止尝试；派生 ZIP 大小未知，不以源档案体积作为硬门槛。
3. 档案页单独显示中转占用和浏览器剩余配额，并提供清理按钮。统计文件大小失败仍可确认清理。
   只删除 `doubak-export-staging`，不碰原始档案；与打包共用 Web Locks，不能清理其他面板正在打包的文件。
4. 成功下载后的中转保留。手动清理或下次导出前，需确认浏览器下载已完成／取消；不以固定等待时间推断下载完成。
   清理时撤销当前面板持有的旧 object URL；其他面板持有的 URL 可能延迟释放，浏览器也可能延迟回收空间。
   清理失败明确报告，不再静默吞掉。
5. 错误提示区分浏览器存储配额和物理磁盘空间，保留原始错误，并给出清理中转、检查两处磁盘、逐份导出整条链的办法。
   不建议清除扩展数据或删除尚未确认外部副本的档案。目录导出与 ZIP 重打包的恢复方式分别说明。
6. Worker 每次从根目录重新打开目录；只读 Worker 不创建缺失目录。扫描期间遇到 NotFoundError 重列一次，
   持续失败仍报告错误，不无限重试、不静默丢弃档案、不缓存失败结果。

## 验证与边界

针对性测试执行实际导出、导入共用复制逻辑和面板事件，覆盖：

- ZIP 初始化／写入／close／getFile 配额失败，清理失败、再次导出、跨面板锁、用户取消清理；
- 失败不交付下载、不登记已导出；整链 ZIP 立即停止、目录整链继续；
- 系统 unzip 解包及原始文件逐字节比较；目录原子写入失败回滚；
- 目录删除／重建、只读不建目录、扫描瞬时与持续错误；
- 配额不足预检、估算不可用、统计失败仍可清理。

没有修改档案格式、包内布局、权限或浏览器最低版本，没有增加 downloads 权限。
`<a download>` 无下载完成通知，浏览器下载阶段的失败仍需用户在下载列表确认。
此轮故障注入覆盖了代码路径；不能替代用户实际磁盘用尽的 Firefox 环境复测。
