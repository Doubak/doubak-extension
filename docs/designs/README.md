# 设计文档目录

这里存放跨模块／跨仓库的功能设计、实现核对与专题审计。按**当前 main 的实现状态**归档，
不以 issue 是否关闭、版本是否发布或所有浏览器人工测试是否完成作为唯一判据。
本次逐项核对：2026-11-12；只有本仓库存在 `docs/designs/`，相关规范与下游实现仍分别维护在兄弟仓库。

## 每个目录存放什么

| 位置 | 内容与维护规则 |
| --- | --- |
| 本目录 `./` | 尚未实现或只完成部分范围的设计，以及仍用于跟踪缺口的实现核对。保留原方案，不因某个子功能完成就整份归档。 |
| [`done/`](done/) | 已实现的限定范围设计、对应验收记录，以及已完成修复的专题审计。保留原日期、决策与验证限制，后续修正可以继续补记。**已实现不等于已发布，也不等于所有人工测试均完成。** |
| [`fixtures/`](fixtures/) | 设计调查用的样本和来源证据，不是运行时数据，也不自动等同于已落地的测试夹具。 |
| [`fixtures/subject-series/`](fixtures/subject-series/) | 同系列作品提案的公开目录配置片段、来源与摘要；提案尚未实现，样本留在原位置。 |

## 后续如何归档

先核对当前代码、测试和验收记录，再移动已实现的设计与相关文档；部分实现的总设计继续留在本目录。
移动时修正相对链接、各仓库 README 和网站指向 main 的链接。固定到历史 commit 或 release tag
的链接保留原路径，因为那些版本中的文件没有移动。不要把历史测试数量或“当时未发布”的记录改写成当前状态。
