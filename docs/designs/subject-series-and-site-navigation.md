# 「同系列作品」归档、修订与站内导航

状态：设计提案，尚未实现。调查日期：2026-10-26。
范围：data-specs、data-parser、site-generator、extension；可涉及 importer 与 export-adapters 的兼容检查。
本次只提交设计，不改变抓取行为、不重新发布 sample 站点。

## 1. 结论与边界

将豆瓣「同系列作品」保存为**某个作品详情页在某次捕获中提供的一份目录快照**，
放在 `subjects.ndjson` 的修订字段里。生成站点在现有作品页中增加系列导航，
优先链接本次确实生成的本地作品页；未归档条目只显示名称与「本档案未收录」。

不建立猜出来的全局系列实体，不合并各季的标记、评分或短评，不改变 `movie/<id>.md`
永久路径。列表出现、增加、减少、重排都属于目录观测变化，不是用户行为。
没有这一字段的旧 canonical 照常生成；新页面没有展示这一栏，也不能清空旧证据。

第一版优先解析已捕获详情页中 `_CONFIG` 的系列数据字面量，也支持有实证的静态栏目。
不递归抓同系列条目、不自动追「全部」链接。本地档案已经保存了大量完整的成员数组，
不需要先执行豆瓣脚本或取得浏览器渲染后的 DOM 才能提取。
「全部」的响应若不在 WARC 里，离线解析就不可能恢复它。
**列表可能只是预览，也不能假定它等于一个电视剧的所有季。**

## 3. 设计决策

本节列出不可被实现细节改变的约束：

1. 一个详情页只为它自己的列表作证；不把 A→B 自动写成 B→A，更不推导 A→B→C 的传递关系。
2. 新的一次可读列表是新快照；不能把所有历史列表取并集当作当前列表。
3. 未抓、未展示、结构不认识与明确空列表分别处理；缺字段不构成删除证据。
4. 来源时间来自真正提供系列证据的 detail capture，不能借用较晚的标记页时间。
5. 本地作品页是否存在，以本次筛选后将输出的页面集合为准。关系不会创建用户标记。
6. 同一批字节在 Node 和扩展导出中产生一致结果；没有网络和 enricher 仍可构建。

## 4. Canonical 数据契约

### 4.1 一个可选的 subject 字段

在 `subjects.ndjson` 的 `revisions[].fields` 新增可选对象 `series`。
使用现有 subject 主键 `(medium,id)`；电视剧继续属于 `movie`，不引入新的媒介值或文件。
以下为**合成示例**，不是从真实 HTML 抽出的结果：

```json
{
  "kind": "douban_same_series",
  "source": "embedded_config",
  "series_url": "https://movie.douban.com/series/EXAMPLE",
  "items": [
    { "medium": "movie", "id": "10001", "title": "示例剧 第一季", "season_label": "第一季" },
    { "medium": "movie", "id": "10003", "title": "示例剧 第三季", "season_label": "第三季" }
  ],
  "scope": "partial",
  "claimed_total": 4,
  "more_url": null
}
```

| 字段 | 第一版写入规则 |
| --- | --- |
| `kind` | 固定 `douban_same_series`，表示已识别配置 / 栏目提供的豆瓣同系列目录关系 |
| `source` | `embedded_config` 或 `rendered_section`，说明证据载体；空占位 div 不算 rendered_section |
| `series_url` | 已见配置中的上游系列 URL；无系列配置的空串归为 `null`，原始空串仍在 WARC；不能代替作品主键 |
| `items` | 来源提供的全部条目，按 JSON 数组 / DOM 顺序保留；每项以 `(medium,id)` 标识，同一 ID 的图片 / 标题链接合为一项 |
| `items[].title` | 配置 / 栏目提供的名称，按载体正确解码；没有可读标题为 `null`，不根据其他作品名猜季名 |
| `items[].season_label` | 可选 string / null，从 `SERIES_SEASON_NAMES[id]` 原样读取；不把 null 当作无关项、不解析成猜测的季序号 |
| `scope` | `partial`：明确还有未展示内容；`complete`：有经过夹具确认的完整枚举证据；`unknown`：无法判断范围 |
| `claimed_total` | 页面声称的非负整数或 `null`；不推算，不减去当前作品，不当作完整性证明 |
| `more_url` | 本栏目明确提供的「全部 / 更多」链接的原始 href（实体解码后），或 `null`；只作来源线索，不意味着已抓取其目标 |

`kind`、`source`、`items`、`scope` 是这一对象的结构必填键；名称、计数、系列 / 更多链接均可未知。
schema 对对象允许附加属性，`kind` / `source` / `scope` 用可扩展字符串词表并在 prose 定义已知值。
第一版 producer 只输出上述已知值。未知 source 不套用自项 / 总数口径，scope 降为 unknown。
未知 scope 的 reader 按 `unknown` 处理；未知 kind
不套用「同系列」语义，跳过这一模块并诊断，不让整个站点失败。

`scope: complete` 只表示**此次该来源列举的集合完整**，不是「世界上全部作品」；
它也不能推导用户是否看过、是否删除标记。非空列表若没有足够完整性证据，始终输出
`partial` / `unknown`，即使 `items.length === claimed_total`。
已见 embedded_config 的 items 全是其他作品，claimed_total 包含当前作品；不手工把当前项
插入 canonical 数组。以后若 rendered_section 包含当前作品，则原样保存，投影隐藏自链接。
不同载体的计数口径不得混用，也不显示「已看 2/4」「还差两季」之类比例。
对嵌入数组不设五项上限；即使 scope 保持 unknown，也完整展示已捕获的 10 / 85 项。
数组的全部字节可读，不等于已经证明平台业务枚举完整，这两个结论要分开。

不用作品标题、首季 ID、列表成员的 hash 或最小 ID 作为系列主键。它们都会随改名、
新增前传、拆分或合并而变化。豆瓣已经提供 series_url，可从准确 `/series/<token>` 路径
导出平台系列标识用于将来的索引；保留 URL 证据即可，不必另复制一个 ID 字段。
这个上游标识不能重写原有作品 ID 或 URL，也不能抹平旧来源的分歧。

### 4.2 缺失、空与部分列表

| 这次输入 | 系列字段及后续行为 |
| --- | --- |
| 旧 canonical 没有 `series` | 完全合法；没有可显示的直接证据，不报「损坏」 |
| 只有标记列表页，未抓详情 / `skip_catalog` / catalog 段已删 | 首次省略字段；已有值原样保留，本次 observation 标 `omitted_fields: ["series", ...]` |
| 正常详情页既无可读配置也无已识别栏目 | 同上；模板差异、旧页面和平台隐藏不能解释为「不再属于系列」 |
| 空 `#series-items`，但有有效 `_CONFIG` | 读取配置；不能把空 DOM 当空系列，也不能因此漏掉数组 |
| 标题在但容器不认识、未闭合、全部条目解析失败 | 不更新该字段；保留旧证据，发可定位到 capture 的诊断 |
| 已识别容器中部分条目解析失败 | 保留成功的正向引用，scope 至多 `partial`；记录诊断，不解释未识别项为退出系列 |
| 新的非空可读列表 | 保存这一份快照，替换投影所用的旧快照；历史不丢，不做跨时间并集 |
| 有效配置：数组空、series_url 空、total 0 | `items: []`、`series_url: null`、`scope: complete`，明确无系列配置；仅清空该来源的当前列表 |
| 有效配置：数组空、有 series_url、total 1 | `items: []`、`scope: complete`，保留系列 URL；当前作品是唯一成员，不称作「没有系列」 |
| 验证码、登录页、gone、未知 verdict、坏字节 | 沿用摄取拒绝规则，不生成空列表或关系删除 |

**没有栏目不是明确空列表。** §2.3 已有明确空配置的真实夹具，可对这一经过验证的
完整配置启用清空分支；丢失键、空 shell、配置截断和未知模板仍没有清空权限。
`series: null` 不由新 producer 输出；reader 遇到它按未知处理并诊断，不将其当作清空。

完整空值是一个字段的正面观测，不是用路线缺失推导删除，和 `absence_authority`
是两套概念。即使公开抓取的 authority 恒为 `none`，仍可以保存页面明确展示的列表；
反过来，全量抓取也没有权力把一个缺失栏目解释成删除。

### 4.3 摘要、顺序与来源

`digests.series = fieldDigest(fields.series)`，使用现有通用摘要规则；缺字段也缺摘要。
不为 series 添加摘要豁免，不改通用 `fieldDigest()`。数组顺序有意义：页面顺序改变
可以产生目录修订，但不叫「新增一季」；同字段的对象键序不会造成修订。
不采栏目评分、评分人数和缩略图 URL，也暂不投影配置的 year / UPDATED，避免为导航
引入无关的频繁变化和资源依赖。series_url 和 season_label 作为字段内容参与摘要。
`more_url` 保留原始值，跟踪参数改变可能产生目录修订；展示层的变化摘要忽略仅此
字段的差异。先保真，若实测确有大量噪声，再单独设计原始值 / 比较 key，不能暗改摘要规则。

每次提供 series 的 observation 直接引用详情页自己的 `bundle_id`、`capture_ids`、
`observed_at`、`surface`，authority 为 `none`。不把来源时间放进 series 对象，
否则列表没变也会每次开新修订。
同内容重复捕获延长修订并追加 observation；列表页或无栏目页携带的旧 series 值
必须在 `omitted_fields` 中声明，不能延长「最后确认系列列表」时间。

生成器从**未省略 series 的 observation**取该列表最后一次实证时间和出处。
不能直接用整个 subject 的 `last_observed_at`，它可能只是较晚的一次标记列表捕获。
新版 parser 的初次提取、不同 parser_version 之间的差异不描述为豆瓣编辑。

## 5. Parser：按时间重放详情证据

### 5.1 不能只往现有 details Map 多塞一个字段

当前实现会让最晚详情字段出现在早期列表页的修订里，并且详情自己不能驱动 subject
新修订。如果只加 `series: detail?.series`，后续抓到了新列表、但没有新的标记页时，
变化可能根本进不了 canonical。这个问题必须和系列支持一起解决。

建议拆成两个步骤，仍只读每个 payload 一次：

1. 抽取时收集小型的 subject 字段补丁和来源，不缓存全部 HTML。
   标记列表补丁携带 title、cover、raw_meta 等列表字段；详情补丁携带 info、aliases、series
   中此次真正有证据的字段。标记本身的 identity / 修订逻辑不改。
2. 所有输入抽取完成后，先建立有真实标记列表证据的 subject key 集合，再按
   `(observed_at 的时间值, bundle_id, capture_id, 补丁种类)` 确定性全序重放这些 key 的补丁。
   字符串 tie-break 用明确字节序比较，不依赖宿主 locale 或输入目录顺序。

详情只补充这一集合中的作品，不因列表引用 B 就创建 B 的 subject 或 mark。
允许时间更早的详情先形成只有已知详情字段的 subject 修订；以后列表补齐标题等，
不把未来标题反填到过去。若整个输入没有 A 的标记证据，则单独的 A 详情仍不创建记录，
保持现有范围边界。处理完标记后再判断资格，避免详情先于列表时被错误丢弃。

每个补丁与此前 subject 已知字段合并；缺少的字段只携带旧值，不清空。
subject observation 重新构造自己的 `omitted_fields`：至少覆盖已定义 subject 字段中
此补丁未提供的字段，不能直接复制 mark 上的 `tags` / `rating` 省略信息。
保留已有 cover 摘要豁免及下架条目标题规则；info / aliases 也沿其真实 detail 时间写入，
不再经过「全局最新 detail 回填所有历史」的捷径。各字段的空值判据仍按自己的规范，
不能把系列栏的规则机械套到所有元数据。

列表页提供的标记状态、评级、短评不会因目录补丁发生修订。由于纠正了 detail 时序，
subject 修订数可以增加，旧的「修订数恰好 N」测试要核对内容和来源后再更新。
发布说明须说明需要从原 WARC 重解析；不能对旧 canonical 就地补一个当前列表冒充历史。

### 5.2 抽取边界

在 `extract-subject.js` 增加纯函数 `extractSeries()`，内部返回
`{ value?, diagnostics }`，由 `extractSubjectDetail()` 带回。`value` 不存在表示未观测到，
与合法空列表分开。**首选已实测的 `_CONFIG` 载体**，不能要求 `#series-items` 存在，
也不能要求空容器里必须有标题或卡片。配置只能来自真实 script 元素里顶层的已知赋值，不能来自
评论、HTML 注释、JSON-LD、其他字符串中的同名字样。

受限数据读取流程：

1. 在 script 边界内，用识别字符串、转义和注释的扫描器定位 `_CONFIG` 对象与字段；
   校验 `SUBJECT_ID` 与详情 URL 的作品 ID 相同。多份冲突配置或主体不符时省略 series 并诊断。
2. 平衡提取 `SERIES_OTHER_SUBJECTS` 数组与 `SERIES_SEASON_NAMES` 对象，只对它们的 JSON
   值调用 `JSON.parse()`；不执行 `eval`、`Function`、VM 或页面脚本，也不引入通用 JS 解释器。
3. 外层对象含未引号键和单引号字符串，不是 JSON。对 `SERIES` 的两个已知字段使用受限
   字符串字面量读取；不能全局替换单引号或把任意表达式求值。遇到函数、拼接、getter 等
   未支持形状就诊断，不执行。总数只接受非负十进制整数文本，并检查安全整数范围。
4. 每项验证 ID、URL、标题类型；季名按对应 ID 读取，缺键省略、null 原样保留。
   配置为 JSON / script raw text 语义：JSON 解码后**不要再对整个脚本做 HTML 实体解码**。
   若未来模板确实多包了一层实体，必须为该变体单独取证。
5. 数组、系列 URL、总数存在且匹配明确空配置时，才允许写空状态。
   缺字段不是空数组；成员数量与该来源声称范围不符时保留正向证据，scope 至多 partial，
   并记录诊断。非空数组配空系列 URL 也不能冒充明确无系列。

有已取证的 rendered_section 时可走静态栏目路径。两种载体同页出现，优先使用完整可读
配置，静态预览作交叉核对，不合并成另一份集合；静态项与配置冲突时诊断并降级范围。
配置不可读但静态栏目有正向证据时可使用后者，必须说明降级；静态空壳没有此资格。
静态路径限定已验证的容器边界和栏目标题，不匹配简介、影评或推荐区的作品链接。

用 HTML 属性读取辅助函数处理单双引号、空白、实体和嵌套节点。没有闭合边界时不延伸
到整页末尾以免把推荐区吞进来。不要猜一个全站 CSS ID 写进实现后只用人造夹具自证。

作品链接用 `new URL(href, detailUrl)` 解析并验证协议、准确 host 和完整路径
`/subject/<数字>/`（允许经过明确规则处理的末尾斜杠及 query）。拒绝凭据、外站、
`javascript:`、伪造子域、`/photos/` / `/reviews/` 子路径。不要直接复用当前宽松的
`subjectRefOf()` 子串匹配来建立关系。只接受 movie 来源，不以数字 ID 跨媒介关联。
静态标题实体解码一次，配置标题只做 JSON 解码，结果都留作文本而不执行 HTML；
缺标题也不从相邻推荐卡片借一个。
同一条目首次出现决定顺序，后续重复链接只补齐尚缺的标题；相互冲突的非空标题
按确定性规则保留首个并诊断，不生成第二个成员。被省略号截断的名称按显示文本保存，
只有真实夹具证明同一卡片另有完整 title / alt 时才采用它，不能根据季数拼出完整名称。

`series_url` 必须验证准确 movie.douban.com host 和 `/series/<字母数字 token>` 路径；
不能以子串匹配信任伪造地址。未知变体保留在 WARC 并诊断，不能因此放行新请求。
`more_url` 的原始 href 作为数据保存，但不能直接放进 HTML 或抓取队列。
实际导航 / 请求必须另经过 URL 解析和白名单检查；暂不识别的 endpoint 保留为证据，
不构造猜测的 API。诊断仅记录原因、来源 key / capture，不包含整页或第三方评论。

### 5.3 幂等性、时间冲突和资源

重复 bundle / capture 先沿现有规则去重；同一详情重复导入不复制关系。
同一来源、同一 observed_at 的冲突列表仍按确定性规则保留全部观测，并发出冲突诊断；
排序结果只决定展示选择，不能声称知道同秒内真实先后。站点在这种情况下显示
「同一时间有不同列表记录」，不生成先删后加的时间叙述。

使用每个 subject 的稀疏补丁保存详情历史，空间约为提取后的字段总量；不保存全量 HTML。
大系列按实际条目数线性处理，不设「超过 5 / 10 条就截掉」之类业务上限。
如果为资源保护设置字节 / 条目上限，触发后必须降级 partial 并诊断，不能装作完整。

## 6. 生成站点：作品页里的系列导航

### 6.1 第一版页面体验

保持当前作品页标题、自己的短评和每季独立的「说过什么」历史。
在短评之后、较长的作品信息和个人历史之前，增加普通 Markdown 段落与列表：

```text
同系列作品
豆瓣作品页于 2026-10-20 提供的列表 · 仅收录页面可见部分
当前作品：示例剧 第二季

• 示例剧 第一季       看过 · ★★★★☆        [站内链接]
• 示例剧 第三季       想看                 [站内链接]
• 示例剧 特别篇       本档案未收录          [纯文本]

页面标示「全部 8」；本次记录含 4 个条目，不保证包含全部系列作品。
```

列表省略自项，并用「当前作品：…」的单行上下文在需要时说明当前位置。
`本次记录含 4 个条目` 按保存的 distinct items 计数，包含
来源确实显示的自项；链接列表数量因此可能少一项。scope 未知时改为「列表范围未知」。
只有真实 complete 且自项规则已核实，才可以说明「该页面的完整列表」。

按来源顺序展示，不把顺序改称「观看顺序」；不从标题猜季数，不自动推荐补看。
本地条目名称用本地 subject 当前可用标题，缺失时回退关系中当时的标题，最后回退
`作品 <id>`；历史差异仍使用各快照自己的名称。关系标题不得写回目标 subject。
评分和「看过 / 在看 / 想看」取本站同一账号投影，未有标记绝不显示「没看过」。

第一版使用文字列表，不新增封面下载；未来可复用已验证的本地图，但绝无远程图片 fallback。
小屏自然换行；状态有文字，不只靠颜色；长列表全量静态展示，不只加载前五项。
无 JS、`file://`、浅色 / 深色主题均可读。无直接或可用间接证据时不输出空模块，
也不在每个旧作品页堆一条「请重新抓取」提示。

### 6.2 链接的判据与稳定地址

在账号与可见性过滤之后，由 `buildPages()` 将实际要生成的作品路径建立
`Map<medium:id, markdownPath>`，关系 renderer 使用这一表。
本地 link 继续采用 `../movie/<id>.md`，由 Hugo 的 render hook 转 `.html`；
不写根绝对 URL，不让子目录部署或本地打开失效。

没有输出目标页时显示纯文本「本档案未收录」，沿用作品类链接不默认回退站外的规则。
`more_url` 不作为「查看本站全部」按钮；可保留现有作品的豆瓣原页出处链接，明确为站外来源。
未来如果增加「去豆瓣查看全部」，必须明标站外、验证目标，并说明不属于离线档案；
第一版不需要这个入口就可完成导航。

系列变化不会移动 / 改名 / 删除已有 `movie/<id>.md`，也不会生成一个以成员 hash
命名、下次重抓就失效的系列页。首页数量、各状态数量、搜索条目数依然统计实际作品，
不把每次被引用都算成一部作品。站内搜索无需把兄弟作品的名称重复灌进每一部的全文索引。
第一版不新增系列聚合页或把影视列表折叠成系列卡片；这些都需要独立的分组身份规则。

### 6.3 单向证据与旧页面的导航

直接列表优先。可在共享投影模块建立最新直接列表的反向索引，帮助 B 没有系列字段时
发现本地 A 的页面曾将 B 列入同系列，但显示在单独的 **「其他作品页中的关联」** 段落：

```text
示例剧 第一季的作品页曾将本作列入同系列（观测于 2026-10-20）。
```

这只是到 A 的本地导航，不生成 B 的 canonical 关系，不取传递闭包，不能借 A→B、B→C
说 A→C。每条反向引用都带来源作品与证据时间；来源作品没有本站页面时，第一版不展示
这条间接导航。关系索引必须在账号隔离后构建，不能借另一个用户的标记显示状态。

只从每个来源最新的有效快照建反向索引，不从所有历史取并集。A 的新列表不再显示 B，
就从 B 页撤下来自 A 的这一条导航；历史仍可在 A 页和 canonical 中查到。
若 B 的旧列表仍显示 A，那是另一个有日期的来源，不能覆盖 A 的新列表。
当本页已经有直接列表时，间接关系仍必须另列并明确出处；明确空列表也不能被反向
索引填成非空的「同系列作品」。这个克制避免陈旧的另一页把已移出的成员偷偷加回来。

### 6.4 列表变化如何显示

主模块只展示最新有效观测，不把历史列表并成一份永远增长的清单。
如有同 parser_version 下的可见内容变化，在独立的 **「系列列表的观测变化」** 小节
用紧凑的日期列表记录「本次多显示 X」「本次未显示 Y」「顺序 / 名称 / 范围变更」。
这与个人「说过什么」时间线分开；日期是观测时间，不是上映、观看或豆瓣实际修改时间。

即使新 scope 为 complete，也最多说「该来源本次未列出」，不宣布作品退出某个真实系列。
partial / unknown 尤其不能称「删除」。相同列表重复观测不增加变化行；仅 more_url
参数变动不增加可见变化行。缺字段 / 提取失败也不产生「列表清空」变化。
不同 parser_version 只注明解析版本不同，不计算新增 / 移除；同秒冲突按 §5.3 标注。

旧列表最后一次确认之后有更新详情但系列栏未知时，主模块仍标原来的实证日期，
并补「后续页面未提供可识别的系列列表」。不能把一次旧观测写成「目前全部系列」。
真正的空列表覆盖主列表后，按来源区分：无系列配置显示「此来源在 <日期> 明确未设置系列」；
有 series_url 且 total 为 1 时显示「此来源在 <日期> 仅列当前作品，没有其他系列条目」。
两者都不恢复旧成员；单成员系列仍保留其上游系列 URL。
全部历史仍留在 canonical，页面只作可读摘要；不依赖额外服务或客户端 fetch。

### 6.5 共享实现位置

建议 generator 增加纯 `series.js`：选取字段证据、生成本页 / 反向引用和目录变化摘要。
`projection.js` 调用它，`pages.js` 提供输出路径表，`markdown.js` 负责文本和链接转义。
主题只负责间距、字号、颜色和链接渲染；不用原始 HTML / `unsafe=true` 才能看到系列内容。
Markdown 导出自身就包含导航，因此扩展 ZIP、文件夹、CLI、第三方 SSG 都能受益。
新增纯文件须加入 extension vendor 清单及 portable 检查，不另造浏览器版本。

## 7. 向后与向前兼容

### 7.1 消费者与档案的组合

| 输入 / 消费者组合 | 结果 |
| --- | --- |
| 旧 bundle + 新 parser | 有原始配置 / 栏目字节即可恢复；没有就省略字段，不要求重新抓取才能导出 |
| 旧 canonical + 新 generator | 原有页面正常生成；无系列证据就无模块；其他页有直接证据时可出现带出处的间接导航 |
| 新 canonical + 旧 generator / exporter | 新字段为可忽略附加属性；原有作品、评分、短评输出保持；旧消费者不展示系列信息 |
| 更新 parser 后重新解析所有旧、新 bundle | 以新 parser_version 从原始观测重建；不混合旧解析结果制造平台变更 |
| catalog 被删除 / 新增量未重抓详情 | 没有新的系列证据；站点继续显示原来的实证日期，不能声称列表已刷新 |
| 更新数据增加、移出、重排 / 改名 | 产生该来源的新快照；路径、标记、统计不变；旧列表保留为历史 |
| 不同作品对同系列给出不同列表 | 分别保存来源，显示直接列表和带出处的间接关系；不投票合成一个真相 |
| 新字段、新 kind / scope 或异常字段类型 | 已知字段可读则继续；未知 scope 不授予完整性；未知 kind / 无效对象跳过模块并诊断 |

兼容性的承诺是**旧工具能继续消费其认识的数据**，不是让它显示新功能。
已知对象里的未知键不妨碍读取，生成器不重写 canonical、不删除未知字段。
series 对象整体损坏、kind 未识别或显式 null 时，不静默倒退到旧快照冒充最新列表；
可给出无法展示最新记录的提示，旧资料仅作为有日期的历史。正常 `omitted_fields`
携带旧值则不同：它明确表达「没有新证据」，可以按 §6.4 继续展示最近实证。

series items 的已知部分可单项容错：无效 ID / 不认识的媒介不得生成链接；
剩余可用项仍可读，但展示范围降级为未知 / 部分并诊断，绝不因跳过无效项变成「完整」。
所有新 object 层使用开放附加属性；新增语义不复用旧 kind 的含义。

### 7.2 版本与迁移

- bundle 格式不变：第一版没有新路由、网络请求、索引结构或权限，原始详情已经由
  `interest.item` 存进 catalog 段。不能为了加一个可离线抽出的字段要求迁移 WARC。
- canonical 使用实施时下一个可用 `1.x` 小版本（调查基线是 `1.3`，因此当前候选 `1.4`），
  parser 同时升版。series 保持可选，不能把旧 subject 判为不完整或无效。
- data-specs 同步 `subject.schema.json`、`FIELDS.md`、`INGESTION.md`、v1 README、
  examples、conformance 与参考 validator。subject 摘要键覆盖检查自然包含 series，
  另加语义检查确保省略、scope、重复项、来源与时序符合本设计；不把仅 JSON 类型校验
  说成已经证明 HTML 枚举完整。
- 旧 canonical 不原地补写；保留原输出供对比，用全部可用 bundle 重新解析到新目录，
  验证后重新生成站点。新旧 parser 之间的 subject 修订数量差异要说明原因。
- 发布可先升级 specs、parser、generator，再同步 extension。旧 generator 的降级可接受，
  extension 中新 parser + 旧 generator 只能称「已保存但尚未展示」，不能宣称整个功能已交付。

## 8. 抓取与刷新：先使用现有证据，再考虑「全部」

### 8.1 第一版沿用既有抓取范围

首次全量 / 选择详情的抓取天然可能保存该配置 / 栏目；公开轻量模式 `skip_catalog` 没有它
也完全正常。新 parser 不联网补全，不因 series 中的新 ID 递归扩展抓取范围。
不会突然抓完整个电影宇宙，也不会增加系列推荐图的下载。

普通增量默认跳过成功抓过的详情，因此**升级解析器不等于刷新豆瓣列表**。
如果原字节已经包含配置 / 栏目，只需重新解析；若要取得后来的变化，由用户使用已有
「重抓作品详情页」能力。`refreshSubjectUrls` 从已知 URL 集合直接排队，所以旧作品
即使不在增量标记列表的新几页里也会刷新。保持其现有节奏、前置门控、挑战处理及恢复行为。

帮助文案需把「从旧档案提取」「重新取得平台最新页面」分开说明。不要为关系信息
默认打开公开模式的详情抓取，也不在打开归档站点时发起刷新请求。
第一版没有定时重抓、强制刷新或自动刷新全部条目的策略。

### 8.2 后续完整列表捕获的条件

§2.3 已证明详情 HTML 自带数组，第一版直接提取它，不因可见预览不足就增加请求。
只有以后确实遇到**已捕获配置也不足**且有可安全捕获的入口时，另一个实现阶段才做：

1. 先检查同一 HTML 的嵌入数据及隐藏容器；对已见 `_CONFIG` 已在第一版完成此项，
   不新增请求；不能混入同页推荐链接，也不能为了得到成员数组去运行 swiper 脚本。
2. 若 `全部` 指向另一个响应，新增有独立语义的 catalog 路由及 intent，例如
   `catalog.series_list`（**暂定名字，不是已经存在的 endpoint**）。请求只来自已捕获、
   已验证详情页里的实际链接，不猜内部 API，不需要的新域 / 权限不得顺带引入。
3. 子捕获用 `parent_capture_id` 指回提供链接的详情。该响应自己的 capture 时间、
   verdict 和字节必须保留；不把它的成员混进较早详情的 observation。parser 接受它时，
   必须验证父来源、所属作品及 scope；缺少父证据时诊断，不猜归属。
4. 新列表属于原作品的后续独立观测。若同一个入口服务多个作品，不能只凭相同 href
   把一次响应盲目分配给所有父节点；要明确可验证的上游身份或分别保留关联证据。
5. 限于已归档作品的系列列表，不沿列表成员继续派生详情或系列。每个来源只跟随
   明确的列表分页；设请求预算、防环和停滞检测，失败 / 截断要标 partial。
6. 多页抓取不能仅凭各页并集或总数相等宣布 complete；需验证分页结束及期间列表稳定性。
   不能证明时保持 partial。不能拿个人标记路线的 coverage 证明一个系列目录完整。
7. 父页的预览已成功、完整入口失败时，保留预览并报告范围缺口，不写空列表。
   成功的完整快照后来遇到更新预览时，主视图使用更新预览并标 partial，旧的完整
   快照保留为历史；不能因旧数据「更完整」就永远压住新观测。

这部分要追加 bundle 词表 / 抓取状态语义、刷新和冷热恢复测试，以及 parser 的来源分派。
既有第一版 series 字段已能表达 partial / complete 与不同时间观测，无需把已发布字段改义。
此阶段未完成时，产品明确承诺「归档页面展示的系列信息」，不承诺「所有季完整收录」。

## 10. 验收矩阵

以下为**实施时必须运行的验收计划**，不表示本次文档工作已经实现或跑过这些测试。
优先测实际 canonical 与 Markdown / HTML 行为，不能只断言存在某个 CSS selector。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 旧 canonical、无详情、skip_catalog、只有旧季数 select | 原有作品正常生成；没有编造系列或强制补抓提示 |
| 空 `#series-items` + 有效配置、推荐区 / 简介 / 评论 / 假配置字符串同页 | 读取真实配置数组；空 shell 不清空；旁边文本和链接不污染关系 |
| 配置中转义引号、括号 / `</script>` 字面量、注释、重复键 / 配置、主体 ID 不符 | 不越过实际 script 边界、不执行代码；不认识 / 冲突时诊断而不清空 |
| 多于五项的嵌入数组、season label 为 null、空数组但有系列 URL | 数组不截断、不丢 null 季名成员、单成员系列与没有系列不同 |
| 真实容器变体、实体、单 / 双引号、重复图片链接、自项、缺标题 | 身份去重与标题保真；自项仅在显示时隐藏；未知模板可诊断 |
| 伪造域名、外站、凭据、JS URL、subject 子路径、同 ID 跨媒介 | 不建立错误关系 / 链接，普通内容仍可生成 |
| 全部 10 但可见 5 项、无总数、总数含不含自项未知、解析一项失败 | 不声称完整、没有观看进度分母；失败项不成为退出系列 |
| 明确空配置与无配置 / 无栏目 / 不认识容器 | 使用真实 no-series 片段验证前者；后者保留旧证据和旧实证时间 |
| 输入 M(t0)、D(t1)、D(t2)，没有 t2 的 mark | subject 在 t1 / t2 有真实来源修订，mark 修订不变 |
| D(t0) 早于 M(t1)，新列表 D(t2) | 不把 t2 字段写进 t0 / t1；detail 顺序不影响最终关联 |
| A 的列表 `[B,C] → 未展示 → [C,D] → 明确空` | 未展示不清空；新列表不是 `[B,C,D]`；变化史保留 B，空值不会回退旧列表 |
| 同列表再抓、打乱 bundle / row、重复导入、同秒冲突 | 幂等且确定；重复只添观测；冲突不伪造时间顺序 |
| A→B、B→C；B 无 series；A 新列表移出 B | 不推导 A→C；B 上反向导航有 A 的日期；A 更新后这条导航消失 |
| B 的旧列表仍含 A，A 新列表不含 B | 分开标来源，不把 B 的旧证据合回 A 主列表；历史事实不被覆盖 |
| 引用未归档作品、有 subject 无输出页、下架作品、删后重标 | 无死链 / 新建 mark / 空壳页；保留稳定路径及独立个人时间线 |
| 两个账号有同作品、不同状态；可见性过滤 | 导航状态只来自所选账号、筛选后的页集合，无跨账号状态泄漏 |
| 未知附加字段、source、scope、kind、类型错误、null | 符合 §7 降级；不能错误获得 complete，也不能让整站失败 |
| 新 parser 与旧 generator / exporter | 原有投影仍可生成；没有新标记、评分、状态或导出条数膨胀 |
| 新增 / 删除 / 重排 / 改名成员后全量再生成 | 作品 URL 不变，旧导航消失，只有必要页面与变化摘要更新 |

双宿主测试须使用同一批脱敏 bundle 比对 canonical、Markdown 文件内容与路径，不能
仅检查两边各自的测试通过。保留 parser 取消、错误字节与资源上限的行为。
必要命令包括 specs validator / conformance、parser 与 generator 相应测试、extension
vendor `--check` / portable / pipeline 测试；实现阶段再跑受影响仓库规定的完整检查。

Hugo 验收在临时输出目录完成：普通与无 series 的作品页、长列表、变化历史、站内跳转，
同时检查窄屏、深浅色、键盘操作、`file://` 与 GitHub Pages 子路径。
枚举实际生成 HTML 的所有内部链接并确认目标文件存在；本功能没有新增远程 `src`，
浏览器断网时仍能浏览导航。对完整站点外部请求的结论必须实测，不能只靠扫描 series 模块。

## 11. 取舍与本次交付

没有采用全局 `series_id` + 无向连通分量：一个错误边就可能把多个系列粘在一起，
移除边又会让 ID 和永久路径改变。已有上游 series_url 值得保存，但不能据此证明
系列身份永不变或跨来源一定一致；未来可据它设计独立聚合页，不改变每部作品 URL。
没有采用永远取历史并集：它无法撤下已经不在新列表里的成员。
没有采用「最新抓取没栏目就清空」：它把模板变化 / 抓取范围差异当作平台事实。
没有采用只改 Hugo 模板：那会让扩展的 Markdown 导出得不到功能。

成本是需要安全读取嵌入数据并修正 subject 详情的时序处理；对只有预览的其他模板，
仍需标注范围。已有 `_CONFIG` 可直接恢复超过五项的数组，无须先扩展抓取器。
收益是旧档案仍可用，新增 / 移出 / 重排都有来源可查，生成站点不会随系列变化破坏
每一季的 URL、评价和历史；将来补抓完整列表也不必推翻这一数据模型。

本次交付为设计、代码 / 归档调查及 9 个公开目录配置片段；具体解析器尚未实现。
已经确认的嵌入数据不依赖实时网页；静态栏目变体、完整入口点击行为仍需后续取证。
不能把搜索索引内容或本次只读探针当作正式 parser 已通过全部验收。
九个片段均已逐一回读对应 WARC 核实原文、capture 时间和 URL，并验证片段摘要与
预期成员数组；未执行其中任何脚本。文档本地链接及 JSON 示例检查通过。

本次已做的兼容性探针：向一个合成 canonical subject 添加上述 `series` 对象、
将其版本改为 `canonical/1.4`，调用当前 generator 的 `project()` + `buildPages()`，
全部输出与没有 series 的输入深比较一致。这只验证现有投影 / Markdown 生成忽略可选字段，
不代表新系列功能、Hugo 或各 export-adapter 已通过 §10 的未来验收。
