# 「同系列作品」归档、修订与站内导航

状态：设计提案，尚未实现。调查日期：2026-10-26。
范围：data-specs、data-parser、site-generator、extension；可涉及 importer 与 export-adapters 的兼容检查。
本次只提交设计，不改变抓取行为、不重新发布 sample 站点。

## 1. 结论与边界

将豆瓣「同系列作品」保存为**某个作品详情页在某次捕获中展示的一份目录快照**，
放在 `subjects.ndjson` 的修订字段里。生成站点在现有作品页中增加系列导航，
优先链接本次确实生成的本地作品页；未归档条目只显示名称与「本档案未收录」。

不建立猜出来的全局系列实体，不合并各季的标记、评分或短评，不改变 `movie/<id>.md`
永久路径。列表出现、增加、减少、重排都属于目录观测变化，不是用户行为。
没有这一字段的旧 canonical 照常生成；新页面没有展示这一栏，也不能清空旧证据。

第一版只解析已捕获的详情页，不递归抓同系列条目、不自动追「全部」链接。
「全部」的响应若不在 WARC 里，离线解析就不可能恢复它。
**列表可能只是预览，也不能假定它等于一个电视剧的所有季。**

从用户正常浏览或既有 bundle 中取得脱敏的栏目片段及其容器边界：短列表、超过预览上限、
电影系列、剧集、无栏目、同页推荐区。核对是否服务端 HTML 已含全表、当前作品是否出现在列表、

若必须新增请求，另按 §8 的后续阶段设计；不能为迁就一个假设的 selector 修改抓取器。

## 3. 设计决策

本节列出不可被实现细节改变的约束：

1. 一个详情页只为它自己的列表作证；不把 A→B 自动写成 B→A，更不推导 A→B→C 的传递关系。
2. 新的一次可读列表是新快照；不能把所有历史列表取并集当作当前列表。
3. 未抓、未展示、结构不认识与明确空列表分别处理；缺字段不构成删除证据。
4. 来源时间来自真正提供系列证据的 detail capture，不能借用较晚的标记页时间。
5. 本地作品页是否存在，以本次筛选后将输出的页面集合为准。关系不会创建用户标记。
6. 同一批字节在 Node 和扩展导出中产生一致结果；没有网络和 enricher 仍可构建。

## 4. Canonical 数据契约

### 4.1 一个可选的 subject 字段

在 `subjects.ndjson` 的 `revisions[].fields` 新增可选对象 `series`。
使用现有 subject 主键 `(medium,id)`；电视剧继续属于 `movie`，不引入新的媒介值或文件。
以下为**合成示例**，不是从真实 HTML 抽出的结果：

```json
{
  "kind": "douban_same_series",
  "items": [
    { "medium": "movie", "id": "10001", "title": "示例剧 第一季" },
    { "medium": "movie", "id": "10003", "title": "示例剧 第三季" }
  ],
  "scope": "partial",
  "claimed_total": 4,
  "more_url": null
}
```

| 字段 | 第一版写入规则 |
| --- | --- |
| `kind` | 固定 `douban_same_series`，仅表示页面明确标注的「同系列作品」关系 |
| `items` | 该栏目实际展示的条目，按 DOM 顺序保留；每项以 `(medium,id)` 标识，同一 ID 的图片 / 标题链接合为一项 |
| `items[].title` | 此栏目显示的名称，实体解码一次；没有可读标题为 `null`，不根据其他作品名猜季名 |
| `scope` | `partial`：明确还有未展示内容；`complete`：有经过夹具确认的完整枚举证据；`unknown`：无法判断范围 |
| `claimed_total` | 页面声称的非负整数或 `null`；不推算，不减去当前作品，不当作完整性证明 |
| `more_url` | 本栏目明确提供的「全部 / 更多」链接的原始 href（实体解码后），或 `null`；只作来源线索，不意味着已抓取其目标 |

`kind`、`items`、`scope` 是这一对象的结构必填键；名称、计数、更多链接均可未知。
schema 对对象允许附加属性，`kind` / `scope` 用可扩展字符串词表并在 prose 定义已知值。
第一版 producer 只输出上述已知值。未知 scope 的 reader 按 `unknown` 处理；未知 kind
不套用「同系列」语义，跳过这一模块并诊断，不让整个站点失败。

`scope: complete` 只表示**此次该来源列举的集合完整**，不是「世界上全部作品」；
它也不能推导用户是否看过、是否删除标记。第一版若没有足够完整性证据，始终输出
`partial` / `unknown`，即使 `items.length === claimed_total`。
若页面包含当前作品，将它原样保留在 items，投影再隐藏自链接。计数是否含当前作品
必须按模板取证；在取证之前，不显示「已看 2/4」「还差两季」之类比例。

不用作品标题、首季 ID、列表成员的 hash 或最小 ID 作为系列主键。它们都会随改名、
新增前传、拆分或合并而变化。若将来豆瓣提供稳定系列 ID，可以新增可选证据字段，
不得用它重写原有作品 ID 或 URL，也不能抹平旧来源的分歧。

### 4.2 缺失、空与部分列表

| 这次输入 | 系列字段及后续行为 |
| --- | --- |
| 旧 canonical 没有 `series` | 完全合法；没有可显示的直接证据，不报「损坏」 |
| 只有标记列表页，未抓详情 / `skip_catalog` / catalog 段已删 | 首次省略字段；已有值原样保留，本次 observation 标 `omitted_fields: ["series", ...]` |
| 正常详情页没有系列栏 | 同上；模板差异、旧页面和平台隐藏不能解释为「不再属于系列」 |
| 标题在但容器不认识、未闭合、全部条目解析失败 | 不更新该字段；保留旧证据，发可定位到 capture 的诊断 |
| 已识别容器中部分条目解析失败 | 保留成功的正向引用，scope 至多 `partial`；记录诊断，不解释未识别项为退出系列 |
| 新的非空可读列表 | 保存这一份快照，替换投影所用的旧快照；历史不丢，不做跨时间并集 |
| 经过真实模板验证的明确空列表 / 无同系列声明 | `items: []`、`scope: complete`，形成新目录修订；仅清空该来源的当前列表 |
| 验证码、登录页、gone、未知 verdict、坏字节 | 沿用摄取拒绝规则，不生成空列表或关系删除 |

**没有栏目不是明确空列表。** 当前还没有明确空列表模板的实证，不能把找不到节点
当成最后一行成功用例；只有取得对应夹具后才启用这一写入分支。
`series: null` 不由新 producer 输出；reader 遇到它按未知处理并诊断，不将其当作清空。

完整空值是一个字段的正面观测，不是用路线缺失推导删除，和 `absence_authority`
是两套概念。即使公开抓取的 authority 恒为 `none`，仍可以保存页面明确展示的列表；
反过来，全量抓取也没有权力把一个缺失栏目解释成删除。

### 4.3 摘要、顺序与来源

`digests.series = fieldDigest(fields.series)`，使用现有通用摘要规则；缺字段也缺摘要。
不为 series 添加摘要豁免，不改通用 `fieldDigest()`。数组顺序有意义：页面顺序改变
可以产生目录修订，但不叫「新增一季」；同字段的对象键序不会造成修订。
不采栏目评分、评分人数和缩略图 URL，避免为导航引入无关的频繁变化和资源依赖。
`more_url` 保留原始值，跟踪参数改变可能产生目录修订；展示层的变化摘要忽略仅此
字段的差异。先保真，若实测确有大量噪声，再单独设计原始值 / 比较 key，不能暗改摘要规则。

每次提供 series 的 observation 直接引用详情页自己的 `bundle_id`、`capture_ids`、
`observed_at`、`surface`，authority 为 `none`。不把来源时间放进 series 对象，
否则列表没变也会每次开新修订。
同内容重复捕获延长修订并追加 observation；列表页或无栏目页携带的旧 series 值
必须在 `omitted_fields` 中声明，不能延长「最后确认系列列表」时间。

生成器从**未省略 series 的 observation**取该列表最后一次实证时间和出处。
不能直接用整个 subject 的 `last_observed_at`，它可能只是较晚的一次标记列表捕获。
新版 parser 的初次提取、不同 parser_version 之间的差异不描述为豆瓣编辑。

## 5. Parser：按时间重放详情证据

### 5.1 不能只往现有 details Map 多塞一个字段

当前实现会让最晚详情字段出现在早期列表页的修订里，并且详情自己不能驱动 subject
新修订。如果只加 `series: detail?.series`，后续抓到了新列表、但没有新的标记页时，
变化可能根本进不了 canonical。这个问题必须和系列支持一起解决。

建议拆成两个步骤，仍只读每个 payload 一次：

1. 抽取时收集小型的 subject 字段补丁和来源，不缓存全部 HTML。
   标记列表补丁携带 title、cover、raw_meta 等列表字段；详情补丁携带 info、aliases、series
   中此次真正有证据的字段。标记本身的 identity / 修订逻辑不改。
2. 所有输入抽取完成后，先建立有真实标记列表证据的 subject key 集合，再按
   `(observed_at 的时间值, bundle_id, capture_id, 补丁种类)` 确定性全序重放这些 key 的补丁。
   字符串 tie-break 用明确字节序比较，不依赖宿主 locale 或输入目录顺序。

详情只补充这一集合中的作品，不因列表引用 B 就创建 B 的 subject 或 mark。
允许时间更早的详情先形成只有已知详情字段的 subject 修订；以后列表补齐标题等，
不把未来标题反填到过去。若整个输入没有 A 的标记证据，则单独的 A 详情仍不创建记录，
保持现有范围边界。处理完标记后再判断资格，避免详情先于列表时被错误丢弃。

每个补丁与此前 subject 已知字段合并；缺少的字段只携带旧值，不清空。
subject observation 重新构造自己的 `omitted_fields`：至少覆盖已定义 subject 字段中
此补丁未提供的字段，不能直接复制 mark 上的 `tags` / `rating` 省略信息。
保留已有 cover 摘要豁免及下架条目标题规则；info / aliases 也沿其真实 detail 时间写入，
不再经过「全局最新 detail 回填所有历史」的捷径。各字段的空值判据仍按自己的规范，
不能把系列栏的规则机械套到所有元数据。

列表页提供的标记状态、评级、短评不会因目录补丁发生修订。由于纠正了 detail 时序，
subject 修订数可以增加，旧的「修订数恰好 N」测试要核对内容和来源后再更新。
发布说明须说明需要从原 WARC 重解析；不能对旧 canonical 就地补一个当前列表冒充历史。

### 5.2 抽取边界

在 `extract-subject.js` 增加纯函数 `extractSeries()`，内部返回
`{ value?, diagnostics }`，由 `extractSubjectDetail()` 带回。`value` 不存在表示未观测到，
与合法空列表分开。优先沿已验证的容器边界和栏目标题匹配，支持已取证的 markup 变体；
不能匹配简介、影评、JSON-LD 文本或「喜欢这部剧集的人也喜欢」里的作品链接。

用 HTML 属性读取辅助函数处理单双引号、空白、实体和嵌套节点。没有闭合边界时不延伸
到整页末尾以免把推荐区吞进来。不要猜一个全站 CSS ID 写进实现后只用人造夹具自证。

作品链接用 `new URL(href, detailUrl)` 解析并验证协议、准确 host 和完整路径
`/subject/<数字>/`（允许经过明确规则处理的末尾斜杠及 query）。拒绝凭据、外站、
`javascript:`、伪造子域、`/photos/` / `/reviews/` 子路径。不要直接复用当前宽松的
`subjectRefOf()` 子串匹配来建立关系。只接受 movie 来源，不以数字 ID 跨媒介关联。
标题解码一次后留作文本，不能执行 HTML；缺标题也不从相邻推荐卡片借一个。

`more_url` 的原始 href 作为数据保存，但不能直接放进 HTML 或抓取队列。
实际导航 / 请求必须另经过 URL 解析和白名单检查；暂不识别的 endpoint 保留为证据，
不构造猜测的 API。诊断仅记录原因、来源 key / capture，不包含整页或第三方评论。

### 5.3 幂等性、时间冲突和资源

重复 bundle / capture 先沿现有规则去重；同一详情重复导入不复制关系。
同一来源、同一 observed_at 的冲突列表仍按确定性规则保留全部观测，并发出冲突诊断；
排序结果只决定展示选择，不能声称知道同秒内真实先后。站点在这种情况下显示
「同一时间有不同列表记录」，不生成先删后加的时间叙述。

使用每个 subject 的稀疏补丁保存详情历史，空间约为提取后的字段总量；不保存全量 HTML。
大系列按实际条目数线性处理，不设「超过 5 / 10 条就截掉」之类业务上限。
如果为资源保护设置字节 / 条目上限，触发后必须降级 partial 并诊断，不能装作完整。

## 6. 生成站点：作品页里的系列导航

### 6.1 第一版页面体验

保持当前作品页标题、自己的短评和每季独立的「说过什么」历史。
在短评之后、较长的作品信息和个人历史之前，增加普通 Markdown 段落与列表：

```text
同系列作品
豆瓣作品页于 2026-10-20 展示的列表 · 仅收录页面可见部分

• 示例剧 第一季       看过 · ★★★★☆        [站内链接]
• 示例剧 第二季       当前作品             [不重复显示为可点击条目]
• 示例剧 第三季       想看                 [站内链接]
• 示例剧 特别篇       本档案未收录          [纯文本]

页面标示「全部 8」；本次记录含 4 个条目，不保证包含全部系列作品。
```

上例第二行只说明当前项语义；实际列表省略自项，并用「当前作品：…」的单行上下文
在需要时说明当前位置。`本次记录含 4 个条目` 按保存的 distinct items 计数，包含
来源确实显示的自项；链接列表数量因此可能少一项。scope 未知时改为「列表范围未知」。
只有真实 complete 且自项规则已核实，才可以说明「该页面的完整列表」。

按来源顺序展示，不把顺序改称「观看顺序」；不从标题猜季数，不自动推荐补看。
本地条目名称用本地 subject 当前可用标题，缺失时回退关系中当时的标题，最后回退
`作品 <id>`；历史差异仍使用各快照自己的名称。关系标题不得写回目标 subject。
评分和「看过 / 在看 / 想看」取本站同一账号投影，未有标记绝不显示「没看过」。

第一版使用文字列表，不新增封面下载；未来可复用已验证的本地图，但绝无远程图片 fallback。
小屏自然换行；状态有文字，不只靠颜色；长列表全量静态展示，不只加载前五项。
无 JS、`file://`、浅色 / 深色主题均可读。无直接或可用间接证据时不输出空模块，
也不在每个旧作品页堆一条「请重新抓取」提示。

### 6.2 链接的判据与稳定地址

在账号与可见性过滤之后，由 `buildPages()` 将实际要生成的作品路径建立
`Map<medium:id, markdownPath>`，关系 renderer 使用这一表。
本地 link 继续采用 `../movie/<id>.md`，由 Hugo 的 render hook 转 `.html`；
不写根绝对 URL，不让子目录部署或本地打开失效。

没有输出目标页时显示纯文本「本档案未收录」，沿用作品类链接不默认回退站外的规则。
`more_url` 不作为「查看本站全部」按钮；可保留现有作品的豆瓣原页出处链接，明确为站外来源。
未来如果增加「去豆瓣查看全部」，必须明标站外、验证目标，并说明不属于离线档案；
第一版不需要这个入口就可完成导航。

系列变化不会移动 / 改名 / 删除已有 `movie/<id>.md`，也不会生成一个以成员 hash
命名、下次重抓就失效的系列页。首页数量、各状态数量、搜索条目数依然统计实际作品，
不把每次被引用都算成一部作品。站内搜索无需把兄弟作品的名称重复灌进每一部的全文索引。
第一版不新增系列聚合页或把影视列表折叠成系列卡片；这些都需要独立的分组身份规则。

### 6.3 单向证据与旧页面的导航

直接列表优先。可在共享投影模块建立最新直接列表的反向索引，帮助 B 没有系列字段时
发现本地 A 的页面曾将 B 列入同系列，但显示在单独的 **「其他作品页中的关联」** 段落：

```text
示例剧 第一季的作品页曾将本作列入同系列（观测于 2026-10-20）。
```

这只是到 A 的本地导航，不生成 B 的 canonical 关系，不取传递闭包，不能借 A→B、B→C
说 A→C。每条反向引用都带来源作品与证据时间；来源作品没有本站页面时，第一版不展示
这条间接导航。关系索引必须在账号隔离后构建，不能借另一个用户的标记显示状态。

只从每个来源最新的有效快照建反向索引，不从所有历史取并集。A 的新列表不再显示 B，
就从 B 页撤下来自 A 的这一条导航；历史仍可在 A 页和 canonical 中查到。
若 B 的旧列表仍显示 A，那是另一个有日期的来源，不能覆盖 A 的新列表。
当本页已经有直接列表时，间接关系仍必须另列并明确出处；明确空列表也不能被反向
索引填成非空的「同系列作品」。这个克制避免陈旧的另一页把已移出的成员偷偷加回来。

### 6.4 列表变化如何显示

主模块只展示最新有效观测，不把历史列表并成一份永远增长的清单。
如有同 parser_version 下的可见内容变化，在独立的 **「系列列表的观测变化」** 小节
用紧凑的日期列表记录「本次多显示 X」「本次未显示 Y」「顺序 / 名称 / 范围变更」。
这与个人「说过什么」时间线分开；日期是观测时间，不是上映、观看或豆瓣实际修改时间。

即使新 scope 为 complete，也最多说「该来源本次未列出」，不宣布作品退出某个真实系列。
partial / unknown 尤其不能称「删除」。相同列表重复观测不增加变化行；仅 more_url
参数变动不增加可见变化行。缺字段 / 提取失败也不产生「列表清空」变化。
不同 parser_version 只注明解析版本不同，不计算新增 / 移除；同秒冲突按 §5.3 标注。

旧列表最后一次确认之后有更新详情但系列栏未知时，主模块仍标原来的实证日期，
并补「后续页面未提供可识别的系列列表」。不能把一次旧观测写成「目前全部系列」。
真正的空列表覆盖主列表后，显示「此来源在 <日期> 明确显示无同系列条目」，不恢复旧值。
全部历史仍留在 canonical，页面只作可读摘要；不依赖额外服务或客户端 fetch。

### 6.5 共享实现位置

建议 generator 增加纯 `series.js`：选取字段证据、生成本页 / 反向引用和目录变化摘要。
`projection.js` 调用它，`pages.js` 提供输出路径表，`markdown.js` 负责文本和链接转义。
主题只负责间距、字号、颜色和链接渲染；不用原始 HTML / `unsafe=true` 才能看到系列内容。
Markdown 导出自身就包含导航，因此扩展 ZIP、文件夹、CLI、第三方 SSG 都能受益。
新增纯文件须加入 extension vendor 清单及 portable 检查，不另造浏览器版本。
