# 公开与多账号归档：实现覆盖核对

核对日期：2026-10-15。对应 extension PR #23、specs PR #5、parser PR #8、site-generator PR #5。
依据：[设计正文](public-and-third-party-account-archive.md)。这是实现验收记录，不能代替设计全文。

## 本轮界面约定

按本轮用户反馈覆盖设计 §6.1.4 的旧线框：不再显示「他人账号」、登录状态刷新按钮或账号 datalist。
概览只在会话探测确认 UID 相同时标注「自己的账号」。输入框预填 `https://www.douban.com/people/`，
只保留此前缀或清空均表示备份已登录账号；可替换为 ID、用户名或完整主页网址（可带查询参数）。
本地账号按钮直接填入 UID。覆盖率以账号为主，记录旁标明「本人登录时备份」或「公开页面备份」。
同一账号只有一种来源时不展示来源筛选；多种来源时默认全部展示，可选筛选，连续性仍各自计算。
选择控件使用面板的颜色、间距、边框和焦点样式。
导出始终显示账号区域：单账号自动选中，多账号明确选择后才能导出。

后续交互修正：用户操作名称由「探测」改为「查看账号」，明确先查看昵称和可备份范围、再开始抓取。
默认本人输入隐藏查看按钮；查询中显示「正在查看…」并防止重复提交，失败可「重试查看」。已有账号按钮仍直接查看。

## 恢复专项验证

- 本人 A 暂停后登录 B：冷/热恢复均拒绝；原 UID、索引和归属不被 B 替换，切回 A 可继续。
- 登录 B 代抓 A 后切 C 或退出；匿名抓 A 后登录 B：拒绝沿原任务继续。
- 冷恢复保留原 `onlyRoutes`、catalog/封面开关、已抓跳过集合、下界、退避与 previous。
- 同目标公开抓取也按操作者 UID 隔离基准；旧公开档案缺失操作者证据不得提供水位线。
- checkpoint 与运行指针冲突、外来 bundle 的 capture id、损坏路线/队列在修复磁盘前拒绝。
- 旧断点只用原始已存主页迁移 UID；无证据不得借当前 Cookie 填档案主人。中止可在离线/换号时执行。
- 概览运行/暂停期间锁住目标输入与范围；「继续」消息没有 UI 新目标参数。

## 2026-10-15：恢复后重复重试的反馈竞争
