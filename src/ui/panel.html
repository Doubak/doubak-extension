环境与存储自检

详细日志

平时不用开。抓取出了问题要来问的时候打开它，重现一次，然后把控制台里 [doubak] 开头的内容贴出来——那是唯一能看出当时发生了什么的东西。
存在本机（IndexedDB），最多保留 1000 条事件与 200 条抓取记录，重新打开后仍在。 事件与抓取记录分开限额：一次全量抓取有数千页， 混在一起会把重试、停机、错误这类稀少而要紧的信号挤掉。 完整的抓取记录在档案的 index.ndjson 中，那才是权威版本。 不会发送到任何地方；里面有 URL 与用户名，贴出去之前请自行脱敏。

使用步骤

  1. 先登录豆瓣。 在任意标签页里登录即可。该扩展与你的所有页面共用登录状态， 密码与 Cookie 均由浏览器管理，本扩展不设任何后端服务器。
  2. 返回「概览」页，点击顶部的按钮。 首次为「开始抓取」，之后为「继续抓取」。默认采用增量抓取： 仅抓取上次之后新增的内容，通常数分钟完成。
  3. 抓取完成后，在「档案」页导出。 此步骤不可省略。未导出的档案仅存在于扩展的存储中； 卸载扩展或清除站点数据都会将其一并删除，且不会给出任何提示。
  4. 想要能直接用的东西，去「导出」页。 结构化数据（NDJSON）、NeoDB 的导入包、或一棵带图片的 Markdown 站点， 均由档案现场算出，直接写入你选的文件夹。 此步骤可以省略——它们随时可以重新生成，而上一步的档案不能。
更换设备，或清除过扩展数据？ 请在「档案」页点击「导入档案…」并选中此前导出的文件夹， 原有档案即可恢复。恢复后仍可继续增量抓取，无需从头抓取一遍。

导出之后：解析与生成站点

这几步现在扩展自己就能做——见「导出」页：结构化数据、NeoDB 导入包、 Markdown 站点，都是现场从档案算出来直接写进你选的文件夹，不装任何东西。
下面这些命令行工具做的是同一件事（用的就是同一份代码）， 适合要改参数、接进脚本、或者只想拿一部分数据的人。 它们也都在你自己的设备上运行，同样不联网； 档案已经在你手中，这几步何时执行、是否执行，都不影响档案本身。
  1. 解析：档案 → 结构化数据。 产出五个 NDJSON 文件（标记、作品、广播、长文、豆列），可直接用 jq 查询。该步骤是纯函数且不联网，如结果有误，重新运行即可。
  2. 生成站点：结构化数据 → 可搜索的网页。 产出一份完全离线也可浏览的个人存档站点， 示例见 sample.doubak.com。
命令以各自仓库的 README 为准。 下表中的命令抄录自撰写本页时的版本，仅便于复制； 工具会持续更新，而本页不会随之更新，因此实际操作时请以对应仓库的 README 为准。

增量抓取跳过的内容

增量抓取的前提是「已抓取的内容均未发生变化」。因此它跳过的不仅是列表页上的旧条目： 凡已抓取过的作品页、日记与影评正文、图片，一律不再重复请求。 跳过的数量记录在「日志」页。
类别增量抓取的处理原因
列表页（看过／想读…）抓取至上次的位置为止 列表按时间排序，回溯至上次的位置即可。
作品详情页仅抓取本次新出现的 评分与短评会变化，但该类页面占档案九成体积。需要最新版本时，请选择「重新抓取可以编辑的内容」。
日记 / 影评正文仅抓取本次新出现的 该类内容可以编辑，因此重新抓取有意义；但这需由你显式指定，并非每次抓取都执行。 同样请选择「重新抓取可以编辑的内容」。
广播仅抓取上次之后发布的 广播发布后不可编辑，已抓取的内容不会再发生变化。
图片（你上传的、作品封面）一律跳过 图片地址即内容地址：更换图片会得到新的地址，同一地址下的字节不会变化。 因此重新抓取得到的必然是同一批字节。该类别没有「重新抓取」选项， 因为该操作不会带来任何新数据。如需重建一份自足的档案，请使用「全量抓取」。
抓取失败的内容会自动重试。跳过名单中只包含确实抓取成功的条目； 被拦截、未抓取到、以及当时已被删除的，下次都会重新尝试。 因此抓取中途出错、遇到验证码或关闭浏览器，均无需任何额外操作，下次继续抓取即可。

导入提示的含义

导入只会新建文件，不会修改扩展内已有的任何字节。该性质并非由确认框保证， 而是写入层本身不具备覆盖能力。因此下列提示均非故障，而是如实反映扫描到的情况。
提示含义与处置
已经有了扩展内该份档案的文件与字节数完全一致，无需重复导入。
补齐上次导出未完成。仅补齐缺失的文件，已存在的文件不作改动。
重复同一份档案在所选目录树中出现多次（例如重复解压）。导入一次即可。
编号撞了扩展内已有相同编号的档案，但内容不同。不予覆盖——同一编号下存在两种内容， 无法判定哪一份正确。如需替换为当前这份，请先删除原有档案。
别的账号该份档案属于另一个豆瓣账号。两个账号的档案混合后，解析器会拒绝整个目录， 且合并之后无法再分离。如确为你本人的另一账号，将提示确认。
不能导该文件夹中的档案不完整：缺少段文件、字节数与 manifest 不符， 或两份档案的文件被放入了同一目录。提示中会指明具体文件。 源文件仍在你的磁盘上，数据未丢失——补齐缺失文件后重新导入即可。
正在抓正在抓取的正是该份档案。请等待其完成，或先在「概览」页中止。

抓取过程中的提示

抓取不会「失败」，只会停下来。 每抓取一页即写入一次磁盘，因此无论在何处停止，此前的每一页均已存入档案。 下表所列各种情形均不会导致已抓取的内容丢失； 真正造成永久损失的只有一种情况——未曾抓取。广播一经删除不留任何痕迹。
提示含义与处置
豆瓣要求验证非故障。请在新标签页中完成验证，返回后点击「继续」。抓取已经停止，不会强行继续请求。
豆瓣暂时限制了访问已经停止且不会重试——继续请求可能导致账号被限制。 请等待 30 分钟以上再继续；恢复后会自动降低请求频率。
登录状态已失效非错误。请重新登录豆瓣，返回后点击「继续」，进度已保留。
上次抓取被意外中断已从断点恢复，没有数据丢失，无需处理。
进度长时间不动某一段抓取可能卡在一个不再返回的请求上（笔记本合盖休眠是已知诱因）。 无需重装扩展：该段连续 5 分钟没有任何动静即判定为卡死，由下一段接管并从断点继续，日志中会留下「抢占」一行。 此时点击「继续」不会立即出现新请求，属正常现象——接管发生在判定之后。已抓取的内容不受影响。
你中止了这次抓取本次抓取不再继续，已抓取的部分全部保留。 档案标记为「中途停下」，缺口如实写入 manifest，受影响路线的水位线不推进——下次仍会重走那一段。 该档案无需删除：解析、导出、重新导入均可正常进行，它也仍可作为下次增量抓取的基准。
这份档案还没收尾manifest.json 于收尾时才写入，因此该档案暂无账号、体积与覆盖率证据。 这不表示损坏：索引与页面均在，解析器照常读取，导出后亦可再导入回来。 缺少的是「已经抓全」的证据，而非内容；它无法作为下次增量抓取的基准。
这次退回了全量抓取未找到可用的增量基准（例如基准档案已被删除）。耗时会显著增加，但不会遗漏内容。

两条容易被忽略的判据

豆瓣自己报出的数量，不能用来判断是否抓全。 实测在同一次抓取中，电影声称 1157 条、实际渲染 1157 条，而游戏声称 293 条、 实际仅渲染 288 条，且缺口位于列表中段。因此判断「是否抓全」应当查看连续性那一列， 而非数量差值。
广播应当优先抓取。 广播发布后不可编辑，且删除不留任何痕迹——未抓取到即为永久丢失。 标记与作品页则可随时重新抓取。
